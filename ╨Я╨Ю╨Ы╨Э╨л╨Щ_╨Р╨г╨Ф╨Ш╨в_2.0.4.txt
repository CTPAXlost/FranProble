3. НОВАЯ ЛОГИКА CI — НЕ ПО ОДНОЙ ОШИБКЕ

scripts/run_ci_checks.sh выполняет и записывает результат каждого этапа:

00 environment
01 source validation
02 clean
03 dependencies
04 Core dependency insight
05 Lifecycle dependency insight
06 Compose dependency insight
07 AAR metadata
08 AndroidManifest
09 resources
10 main Kotlin compile
11 unit-test Kotlin compile
12 unit tests
13 Android Lint
14 assemble APK

Отказ одного этапа не прекращает попытки выполнить остальные. После всех
этапов создаётся 00-summary.txt, а workflow получает exit code 1, если был хотя
бы один провал. Ошибки не скрываются через continue-on-error.

Bootstrap-логи создания Wrapper и установки SDK теперь сохраняются: ранее
агрегатор очищал всю папку ci-logs, что уничтожило бы эти два полезных файла.

4. АУДИТ ДИАГНОСТИЧЕСКОЙ ЛОГИКИ

- System DNS выполняется через runInterruptible и ограничен coroutine timeout.
- Прямой DNS проверяет transaction ID, QR, ровно один исходный вопрос, имя,
  record type и class IN.
- Проверяются границы DNS-пакета и RDATA до чтения.
- Обрезанный UDP DNS-ответ получает LIMITED и автоматически повторяется по TCP.
- FULL mode не прекращает сравнение после первого доступного резолвера.
- TCP/TLS не запускаются без реального IP и получают NOT_TESTED.
- TLS 1.2/1.3, SNI, Host и ALPN разделены.
- Неподдерживаемая локально версия TLS получает NOT_TESTED.
- На Android ниже API 29 ALPN через SSLSocket получает NOT_TESTED, а не ложный
  результат сети.
- Успешный TLS не теряется, если последующая HTTP-проба дала timeout/EOF.
- DoT использует Android trust store и hostname verification.
- SNI matrix намеренно принимает любой сертификат только для чтения Subject/SAN;
  это явно отмечается в отчёте.
- DoH использует заданный IP, выбранную Network и Proxy.NO_PROXY.
- UDP timeout остаётся INCONCLUSIVE; Port Unreachable фиксируется отдельно.

7. ОГРАНИЧЕНИЕ ПРОВЕРКИ

В данной рабочей среде нет Android SDK и полного офлайн-кэша Google/Maven.
Поэтому нельзя честно заявить, что здесь выполнен настоящий assembleDebug.
Следующий GitHub Actions является финальной реальной Android-компиляцией.
Но в отличие от предыдущих версий он не остановится на первой Gradle-задаче:
при ошибке он отдаст один диагностический артефакт со всеми выполненными
этапами и их отдельными логами.
