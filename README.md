# FranProbe 2.0.4

FranProbe — Android-приложение для послойной диагностики сети при режиме разрешённых адресов («белых списков»), выборочной фильтрации DNS, TCP/UDP и TLS/SNI.

## Главное отличие

FranProbe не помечает последующие тесты как `BLOCKED`, если они фактически не запускались. Сбой DNS не превращается автоматически в «TCP заблокирован»: зависимый этап получает `NOT_TESTED` с точной причиной.

## Возможности

- параметры активной сети Android: транспорт, адреса, DNS, маршруты, MTU, VALIDATED, captive portal;
- системное DNS на выбранной активной сети с ограничением времени ожидания;
- прямой DNS по UDP/53 и TCP/53;
- DoT/853 со штатной проверкой сертификата и имени;
- DoH/443 через прямой IP резолвера, HTTP/2/HTTP/1.1 и без случайного системного прокси;
- проверка DNS transaction ID, имени, типа и класса исходного вопроса, RCODE, A/AAAA, CNAME, TTL и truncation;
- проверка границ DNS-пакета и заявленной длины RDATA;
- автоматический повтор обрезанного DNS-ответа по TCP;
- в полном режиме — сравнение системных и прямых DNS-ответов для поиска подмены;
- продолжение проверки напрямую по полученному IP;
- прямой TCP по IPv4/IPv6;
- TLS 1.2 и TLS 1.3 с отдельным статусом, если версия не поддерживается устройством;
- матрица SNI: без SNI и с пользовательским списком имён;
- ALPN `http/1.1` и `h2`; отсутствие поддержки ALPN устройством не считается сетевой ошибкой;
- отдельный HTTP `Host` без SNI;
- сертификат, SAN и совпадение сертификата с SNI;
- успешный TLS и последующая ошибка HTTP сохраняются как два разных результата;
- осторожная UDP-диагностика: отсутствие ответа не считается доказанной блокировкой, ICMP Port Unreachable фиксируется отдельно;
- история последних 20 отчётов;
- экспорт ZIP: TXT, JSON, CSV, RAW.LOG и README;
- временный ZIP экспорта удаляется после сохранения или отмены, а история отчётов исключена из Android Backup.

## Сборка APK через GitHub

1. Создайте пустой репозиторий GitHub.
2. Загрузите **содержимое** этой папки в корень репозитория.
3. Откройте вкладку **Actions**.
4. Запустите **FranProbe Android build**.
5. После успешной сборки скачайте `FranProbe-debug-APK`.
6. Внутри будет `FranProbe-2.0.4-debug.apk`.

Workflow создаёт и проверяет Gradle Wrapper 9.5.0, устанавливает Android SDK Platform 36 и запускает все обязательные этапы:

- проверка структуры, XML, версий и критических защит;
- чистая сборка без старых артефактов;
- полный отчёт зависимостей;
- dependency insight для Core, Lifecycle и Compose;
- проверка AAR metadata;
- обработка AndroidManifest;
- слияние ресурсов;
- компиляция основного Kotlin-кода;
- компиляция unit-тестов;
- запуск unit-тестов;
- Android Lint;
- сборка APK.

Все 15 этапов запускаются за один проход даже после ошибки. В конце workflow всё равно завершается с кодом 1, если провалился хотя бы один обязательный этап. Артефакт `FranProbe-build-diagnostics` содержит сводку, отдельный лог и exit code каждого этапа, а также bootstrap-логи Gradle Wrapper и Android SDK.

## Локальная сборка

Откройте проект в Android Studio с JDK 17 и Android SDK Platform 36. При наличии Gradle 9.5.0:

```bash
gradle wrapper --gradle-version 9.5.0 --distribution-type bin
scripts/run_ci_checks.sh
```

APK появится в:

```text
app/build/outputs/apk/debug/app-debug.apk
```

## Как запускать диагностику

- Отключите VPN, если проверяете сеть оператора напрямую.
- Сделайте один отчёт в нормальном режиме и второй во время ограничений.
- Не меняйте списки доменов между сравниваемыми запусками.
- Для матрицы SNI укажите прямой IP. Если базовый TCP не проходит, перебор SNI не может помочь.

## Статусы

- `AVAILABLE` — получен положительный протокольный результат.
- `LIMITED` — нижний слой прошёл, но следующий этап отклонён или работает иначе.
- `UNREACHABLE` — тайм-аут, отсутствие маршрута или невозможность установить соединение.
- `NOT_TESTED` — зависимый тест не запускался либо устройство не поддерживает сам способ проверки.
- `INCONCLUSIVE` — данных недостаточно для вывода о блокировке.
- `ERROR` — ошибка конфигурации или приложения.

## Конфиденциальность

FranProbe не содержит телеметрии и не отправляет отчёты разработчику. Отчёты остаются во внутренней памяти приложения либо сохраняются пользователем вручную. История отчётов исключена из облачного резервного копирования и переноса данных Android.
