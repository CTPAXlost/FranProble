# FranProbe 2.0.3

FranProbe — Android-приложение для послойной диагностики сети при режиме разрешённых адресов («белых списков»), выборочной фильтрации DNS, TCP/UDP и TLS/SNI.

## Главное отличие от старой версии

Приложение не ставит `BLOCKED` последующим тестам, если они фактически не запускались. Например, сбой DNS не превращается автоматически в «TCP заблокирован». Вместо этого используется статус `NOT_TESTED` с точной причиной.

## Возможности

- параметры активной сети Android: транспорт, адреса, DNS, маршруты, MTU, VALIDATED, captive portal;
- системное DNS на выбранной активной сети;
- прямой DNS по UDP/53 и TCP/53;
- полноценные DNS-запросы по DoT/853 и DoH/443 к контрольным резолверам; DoH поддерживает HTTP/2 и HTTP/1.1;
- проверка transaction ID, вопроса, RCODE, A/AAAA, TTL и признака truncation;
- продолжение проверки по полученному IP без зависимости от DNS роутера;
- прямой TCP по IPv4/IPv6;
- TLS 1.2 и TLS 1.3;
- SNI без SNI и с пользовательским списком имён;
- ALPN `http/1.1` и `h2`;
- отдельный HTTP Host и фиксация первой строки ответа;
- сертификат, SAN и совпадение сертификата с SNI;
- осторожная UDP-диагностика: отсутствие ответа не считается доказанной блокировкой;
- три режима: быстрый, полный и матрица SNI;
- автоматическая история последних 20 отчётов;
- экспорт ZIP: TXT, JSON, CSV, RAW.LOG и README;
- сохранение и повторный экспорт любого из последних 20 отчётов.

## Сборка APK через GitHub

1. Создайте пустой репозиторий GitHub.
2. Загрузите в него **содержимое** этой папки, чтобы `settings.gradle.kts` находился в корне.
3. Откройте вкладку **Actions**.
4. Выберите запуск **FranProbe Android build**.
5. После зелёной галочки откройте запуск и скачайте артефакт `FranProbe-debug-APK`.
6. Внутри будет APK для установки на Android.

Workflow сам создаёт Gradle Wrapper 9.5.0, затем запускает unit-тесты, Android Lint и сборку APK. Ошибки не скрываются через `continue-on-error`. Перед компиляцией workflow отдельно проверяет, что Gradle разрешил AndroidX Core 1.17.0, совместимый с API 36, а Compose зафиксирован на стабильном BOM 2025.08.00.

## Локальная сборка

Проще всего открыть проект в Android Studio с JDK 17 и Android SDK Platform 36. Если Gradle Wrapper ещё не создан, один раз выполните установленным Gradle 9.5.0:

```bash
gradle wrapper --gradle-version 9.5.0 --distribution-type bin
./gradlew clean testDebugUnitTest lintDebug assembleDebug
```

APK появится в:

```text
app/build/outputs/apk/debug/app-debug.apk
```

## Как правильно запускать проверку

- Отключите VPN перед диагностикой, если хотите проверить сеть оператора напрямую.
- Запустите один отчёт на обычной сети и второй во время ограничений.
- Не меняйте списки доменов между двумя сравниваемыми запусками.
- Для матрицы SNI укажите прямой IP сервера. Если базовый TCP не проходит, перебор SNI не имеет смысла.

## Статусы

- `AVAILABLE` — получен положительный протокольный результат.
- `LIMITED` — нижний слой работает, но следующий этап отклонён или отличается.
- `UNREACHABLE` — тайм-аут, отсутствие маршрута или невозможность установить соединение.
- `NOT_TESTED` — зависимый тест не запускался.
- `INCONCLUSIVE` — данных недостаточно для вывода о блокировке.
- `ERROR` — ошибка конфигурации или приложения.

## Конфиденциальность и безопасность

- FranProbe не отправляет отчёты на сервер разработчика и не содержит телеметрии.
- Отчёты хранятся только во внутренней памяти приложения и в файле, который пользователь сохраняет вручную.
- Диагностический TLS-тест намеренно принимает сертификат для анализа его Subject/SAN. Через такое соединение не передаются пароли, токены или пользовательские данные.
- DoH к известным публичным резолверам, напротив, использует обычную проверку сертификата и имени хоста.

## Ограничения диагностики

Приложение не может достоверно узнать внутренние правила оператора. Оно фиксирует наблюдаемую точку отказа. Тайм-аут сам по себе может означать фильтрацию, потерю маршрута или молчащий сервер. Поэтому отчёт сохраняет факты и не выдаёт догадку за доказанный диагноз.
